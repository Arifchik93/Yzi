# Проверка шаблона УЗИ мочевого пузыря и предстательной железы

## Что проверено
- Структура шаблона `bladderprostate.txt`.
- Логика автозаключений в `app.js`.
- База сценариев для автозаключений в `conclusionRules.json` и таблица правил `BLADDER_PROSTATE_CONCLUSION_RULES_TABLE.md`.

## Найденные проблемы
1. Для протокола `bladderprostate` ранее использовался не профильный сбор контекста (`collectThyroidContext`), из-за чего специфические признаки мочевого пузыря/ПЖ почти не участвовали в автоматическом заключении.
2. Поле `complexRules` для `bladderprostate` в `conclusionRules.json` содержит расширенный набор сценариев, но эти сценарии не применялись в коде.
3. Извлечение объёма (мл) для простаты и остаточной мочи требовало более устойчивого парсинга (через метку `мл`, а не первое число в строке).
4. В шаблоне не хватало отдельной строки по ЦДК для очагов стенки мочевого пузыря и поля для ПСА (если известно), что снижало точность и клиническую интерпретируемость отчёта.

## Что улучшено
1. Добавлен профильный сбор контекста для `bladderprostate`:
   - признаки мочевого пузыря (наполнение, доступ, контуры, стенка, содержимое, конкременты, выбросы, дилатация, остаточная моча, очаги);
   - признаки простаты (объём, контуры, структура, эхогенность, уретра, очаговые изменения, периферическая зона, семенные пузырьки).
2. Добавлен отдельный блок клинических эвристик автозаключения для `bladderprostate`:
   - ограниченная информативность при плохом наполнении;
   - признаки инфравезикальной обструкции;
   - подозрение на опухоль мочевого пузыря при васкуляризованном очаге;
   - вероятный сгусток/детрит при подвижном аваскулярном содержимом;
   - цистолитиаз;
   - признаки тяжёлого нарушения оттока;
   - ДГПЖ с обструкцией;
   - подозрительный очаг ПЖ (онкориск);
   - хронические фиброзно-кальцинатозные изменения ПЖ.
3. Улучшено извлечение объёма: добавлена функция парсинга последнего значения в `мл`.
4. В шаблон добавлены:
   - строка `ЦДК стенки/очагов мочевого пузыря`;
   - строка `ПСА (по данным направления/со слов пациента)`.

## Рекомендованные следующие шаги
1. Перевести `complexRules` для `bladderprostate` из «текстовых условий» в машиночитаемые критерии (токены/поля/пороговые значения), чтобы использовать весь набор сценариев без эвристик.
2. Добавить unit-тесты на генерацию заключений для типовых кейсов:
   - ДГПЖ + высокая остаточная моча;
   - подозрение на опухоль мочевого пузыря;
   - конкремент мочевого пузыря;
   - ограниченная информативность исследования.
3. Ввести приоритетизацию конкурирующих заключений (urgent > high > moderate > benign) с подавлением менее значимых формулировок при критических состояниях.
4. Добавить предупреждение в UI при неполном заполнении ключевых полей (остаточная моча, выбросы, стенка, очаги).
